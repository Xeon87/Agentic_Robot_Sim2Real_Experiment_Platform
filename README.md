## V4.5
**V4.5**（鸡蛋放进蛋托对不准 + 夹蛋时指尖碰桌面 + V4.4 闪退加固）
1. **放蛋对不准——找到并修好的原因**：
   - **夹着的鸡蛋位置用错了（主要原因，约 12 mm）**：夹蛋时鸡蛋被动爪推到固定爪上，蛋心离固定爪面约 20 mm；V4.3/V4.4 放蛋时却按 8.5 mm 补偿。V4.5 在夹蛋那一刻记下“蛋心在夹爪坐标系里的实际位置”（离线替身实测 (0, 20.3, 0) mm），放蛋时用同一个量。
   - **对准的是蛋心，不是先进槽的下端**：立蛋没到完全竖直时（以前从 −75° 开始试，倾斜 15°），下端会横向偏约 7 mm。V4.5 改为把**鸡蛋下端**对准槽心，倾斜多少都自动抵消；而且先试 −90° / +90°（真正竖直）。
   - **槽位按外框等分**：蛋托边沿、翻开的盖子会让外框变大，槽位整体偏移。V4.5 用深度图里每个空槽的“凹坑”找真实槽心，并据此拟合槽距和整体偏移（离线：外框偏 30 mm 时，旧算法最大偏 >10 mm，新算法 <2 mm）。可在 `config/egg_carton.json` 填实测槽距（用尺量相邻两槽中心距离），不填也能工作。日志里蛋托一行会显示“槽位按 N 个槽穴凹陷拟合：整体偏移 …，槽距 …”。
   - **放蛋前的腕部相机复查**：以前立蛋后腕部相机朝侧面，复查被跳过。V4.5 在转腕立蛋**之前**，夹爪朝下停在槽位正上方 12 cm，用腕部相机复测槽位；可信且偏差 1.5–15 mm 时按新位置重新规划下插。看不清（可能被夹着的鸡蛋挡住）或偏差过大时沿用主相机位置，日志会说明。
2. **指尖碰桌面——原因和修改**：
   - 安全区的 z 检查以前检查的是**胶垫中心**（下限 桌面 + 6/8 mm），而指尖在胶垫中心下面 10 mm，动爪张开时最多再低 1.5 mm——所以安全区实际允许指尖到桌面以下。V4.5 起检查点改为**最低的指尖**（固定爪 / 动爪、任意开口）：规划时要求离桌 ≥ 5 mm，执行时（所有 SO-101 任务的硬底线）≥ 3 mm。
   - 夹持高度：胶垫中心对准鸡蛋赤道（42 mm 蛋 → 21 mm），固定爪指尖离桌 11 mm、最低指尖 9.5 mm（以前 8.5 mm、且没检查）。小鸡蛋会自动抬高，保证指尖 ≥ 5 mm。
   - 桌面高度取“相机拟合桌面”和“安全区 z_table”中**更高**的那个；两者差超过 15 mm 时拒绝夹蛋（说明手眼标定或安全区桌面高度有问题），日志 `[FAIL] [V4.5 EGG PLAN] 相机测得的桌面比安全区 z_table …`。
   - 下探分两段：先到抓取高度上方 15 mm，最后 15 mm 以 10 mm/s 慢速。
   - 规划时按执行时同样的直线插值点检查关节余量（V4.4 只查两端，曾出现“规划通过、执行时 J6 余量 3.9° 被拒”）。
3. **V4.4 闪退加固**（没有拿到崩溃日志，下面是代码里找到的风险点，都已修）：
   - 「③ 执行 SmolVLA 闭环」「③ 执行顶层 Agent」在**界面主线程**里加载 SmolVLA（硬盘上加载要 10 秒到几分钟），窗口会长时间“未响应”，Ubuntu 会弹出“强制退出”——看起来就像闪退。现在加载都在后台线程，点击立即返回。
   - 后台线程修改环境变量（`os.environ`），与 Tk / X11 / CUDA / RealSense 线程同时读环境变量时可能段错误。现在只在主线程、且只在值变化时修改。
   - 拔硬盘时停止 SmolVLA 进程（最多等 6 秒）改到后台线程；「①」和「③」同时点不会启动两个 SmolVLA 进程。
   - 控制台启动时把上一次的 `logs/console.log` 改名为 `logs/console.prev.log` 保留（以前闪退后重启就被清空）。**下次再闪退，请把 `logs/crash.log` 和 `logs/console.prev.log` 发给我**。
4. **测试情况**：离线测试 `tests/test_v4_5.py`（9 项）通过；V4.1 / V4.2 / V4.4 测试通过（V4.1/V4.2 中夹持高度 18.5/8.5 mm 的断言按设计改为 21.0/11.0 mm）；所有 V3 离线测试与 V4.4 结果一致。**没有在真实机械臂、真实蛋托、真实腕部相机上运行过**。第一次请先用「计划预览 / 悬停」档看日志里的 `lowest_tip_z_mm`、`egg_in_G_mm`、`place_pitch_deg` 和蛋托一行，再跑执行。


**V4.4**（LeRobot + SmolVLA 全部装到移动硬盘 `EMBODIED_AI`；「VLA / LeRobot (V4)」页新增「0. 移动硬盘」区）
1. **为什么**：本机磁盘装不下 torch + CUDA 库（约 7 GB）、SmolVLA 模型（约 2.5 GB，含 SmolVLM2 视觉语言主干）和以后的训练数据 / 训练结果。V4.4 起这些全部放在卷标为 `EMBODIED_AI` 的移动硬盘上，本机只保留 NERO 程序本身。
2. **硬盘上的目录**（自动创建，在 `<EMBODIED_AI>/nero_lerobot/`）：
   - `envs/lerobot/` LeRobot 独立 Python 环境（torch、lerobot[smolvla]）；`python/` uv 下载的 Python 3.12
   - `hf_home/` Hugging Face 缓存（`HF_HOME`）；`models/smolvla_base/` SmolVLA 基础模型
   - `datasets/nero/` 示教录制数据；`datasets/lerobot/` 导出给 LeRobot 训练用的标准数据集
   - `checkpoints/` 内置 NERO VLA 快速微调结果；`training/` LeRobot 真实微调（每次一个文件夹）
   - `cache/`、`tmp/` pip / torch / uv 缓存和临时文件（安装时也不占本机磁盘）；`logs/` 安装、下载、导出、训练日志
   - `activate_nero_lerobot.sh`：终端里 `source` 它就能手动使用硬盘上的环境
3. **控制台怎么用**（「VLA / LeRobot (V4)」页最上面「0. 移动硬盘 EMBODIED_AI」）：
   - 「🔄 检测硬盘」/「挂载 EMBODIED_AI」→「📁 初始化目录」→「🛠 安装 LeRobot+SmolVLA 到移动硬盘」（后台运行，进度显示在下方日志；关闭控制台也不会中断）→「🧪 验证环境」看 torch / CUDA / lerobot 版本。
   - Python 选项：默认「3.12 (uv 装到硬盘 · 最新 LeRobot)」—— LeRobot 0.5 起要求 Python ≥ 3.12，而 Ubuntu 22.04 自带 3.10；uv 会把一个独立的 Python 3.12 装到硬盘上（不动系统 Python）。如果 uv 下载失败，安装脚本自动改用系统 Python 3.10（只能装到 LeRobot 0.4.4）。
   - 勾选「装完自动下载 smolvla_base」时，装好后自动把模型下载到硬盘；之后「SmolVLA 权重」填 `lerobot/smolvla_base` 就会自动用硬盘上的本地副本。
   - 「🧹 本机旧文件→硬盘」：把 V4.0–V4.3 存在 `~/Downloads/cameracalib/...`、`~/Downloads/objectmodels/smolvla_base` 和 `~/.cache/huggingface/hub` 里的数据 / 模型复制到硬盘，复制成功后可选择删除本机原文件；`~/.cache/pip` 只提示大小（可执行 `pip cache purge` 释放）。
   - 「⏏ 安全移除硬盘」：停止后台任务和 SmolVLA 进程、写盘、卸载并断电，然后可以拔下。
4. **SmolVLA 怎么运行**：控制台仍是 `/usr/bin/python3`；点「① 加载 SmolVLA」时，如果控制台自己的 Python 里没有 lerobot，就用硬盘环境的 Python 启动 `NERO_V44_SmolVLA_Worker.py`，推理在那个进程里做（两路相机原图直接以字节传过去）。横幅里的 `SmolVLA=hf_smolvla_ext` 表示正在用硬盘上的真 SmolVLA；`nero_vla_pretrained` 表示没找到硬盘环境 / 模型，用的是内置替身。
5. **LeRobot 真实微调**（第 3 区第二行）：录好示教 →「📦 导出为 LeRobot 数据集」→ 填步数 / batch →「🚀 开始 SmolVLA 微调 (GPU)」（调用 `lerobot-train`，输出到硬盘 `training/`，不上传 Hugging Face，不用 wandb）→ 训练结束自动把「SmolVLA 权重」设为最新结果（也可点「↩ 使用最新训练结果」）→「① 加载」。原来的「⚡ 微调 SmolVLA」改名为「⚡ 快速微调 (内置 NERO VLA)」，它只是内置的小网络，不是真 SmolVLA。
6. **安全规则**：只有真正挂载的硬盘才会被使用（拔掉后残留的空 `/media/<用户>/EMBODIED_AI` 文件夹在本机磁盘上，会被拒绝）；硬盘不在时，安装 / 下载 / 导出 / 训练一律不执行（不会偷偷写满本机磁盘），示教数据临时存回原来的 `~/Downloads/cameracalib/lerobot_datasets`；硬盘被拔出时控制台会提示，并停掉硬盘上的 SmolVLA 进程。
7. **硬盘格式**：最好是 **ext4**。exFAT / NTFS 也能用（自动改为复制模式建环境，且只能用系统 Python）；FAT32 不能用（单文件 4 GB 限制）。挂载为 `noexec` 时程序无法运行，状态栏会提示。
8. **空间**：实测装完共约 16.5 GB（环境 5.9 GB + pip 缓存 3 GB + 模型 / HF 缓存 7.6 GB），所以要求硬盘空闲 ≥ 25 GB（pip 缓存以后可删）。
9. **测试情况**：离线测试 `tests/test_v4_4.py`（8 项）通过，V4.2 回归测试通过。在本开发环境（无 GPU，用文件夹模拟硬盘）**真实跑通了整条链**：安装脚本（Python 3.12 + lerobot 0.7.0 + torch 2.15）→ 下载 smolvla_base 和 SmolVLM2 主干 → 硬盘进程加载真 SmolVLA 并推理（CPU 约 1.2–1.6 s/块）→ 示教数据导出为真实 LeRobotDataset（mp4）→ `lerobot-train` 微调 2 步并保存 checkpoint → 加载训练结果推理 → 闭环执行 3 块（仿真替身后端）。这个过程中发现并修好了 4 个只有真环境才会暴露的问题（`LEROBOT_HOME` 已废弃导致 lerobot 拒绝导入；0.7 版数据集 / 训练是可选扩展包；0.7 版没有 `--wandb` 参数；smolvla_base 的相机名是 camera1/2/3，自动加 `--rename_map`，微调后状态维度以归一化统计为准）。uv 下载 Python 3.12 及失败时退回系统 Python 也都实测过。**没有在你的电脑、真实 EMBODIED_AI 硬盘、RTX 4060（CUDA）、真实机械臂上运行过**；第一次请按 CHANGELOG 的步骤先在「仿真替身」后端试。


**V3.89**（主相机手眼标定加固：红外深度平整簇优先采纳 + PnP 运动学探针与 1D 最优尺度自校准）
1. **红外深度平整簇采纳门限放宽（解决车库长曝光/高增益下白边晕光侵蚀黑边）**：
   - 在 `detect_aruco` 中提取标记中心区域的深度点云并检测平整度（标准差 < 8 mm）；

2. **主相机 PnP 运动学探针与 1D 最优尺度自校准（第二道防线）**：

   - 同时在 $lpha \in [0.70, 1.30]$ 范围内做一维最优尺度网格与黄金分割收敛搜索；
   - 自动纠正打印纸张缩印、手工测量误差及白边晕光带来的系统性尺度缩放（自动恢复 1:1 公制尺度，留一残差由 10–20 mm 直接收敛至 < 2 mm 合格绿标）；
   - 标定结果字典与 `camera_calib.json` 自动记录 `scale_factor` 与 `unified_source`。
